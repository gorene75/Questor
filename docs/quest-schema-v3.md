# Quest schema v3

Successor to v2. Written to be **generated by the builder agent and corrected by a human**, not authored from scratch. Every field below should have a sensible inferred default so an author who ignores it still gets a playable quest.

## What v2 got right, and keeps

The central rule holds: **the model judges, the engine decides.** Anything checkable in code is checked in code. v2's enforcement — exits, `requires`, disposition clamping, derived expressions, validation-before-commit — was proven correct under adversarial models and is unchanged.

## What v2 got wrong

Three failures found in live play, all the same shape: **the schema had no vocabulary for the thing, so nothing enforced it.**

1. A character could leave permanently without her gating flag set, soft-locking the quest. Fixed in v2.1 by `guarded_events`, kept here.
2. Refusing to help produced a dead room with no ending — the model narrated its own stuck state for fifteen turns because nothing said where that branch goes.
3. The model correctly rejected a telephone in 1883 London — but only because it happens to know Victorian London. Nothing declared the era. **An original world would have gotten this wrong, silently.**

The third is the serious one. v2 was proven against a quest whose world the model already knew. That is not a proof for a platform where authors invent worlds.

## What's new, and why each is a separate mechanism

| Layer | Enforced by | Answers |
|---|---|---|
| `world` | Model, against a declared frame | What exists at all |
| `story` (scenes, exits, flags) | Engine, deterministically | What is legal right now |
| `pressure` | Engine triggers, model narrates | What pulls a drifting player back |
| `degradation` | Engine | What failure costs, short of restarting |
| `termination` | Engine | Why nothing loops forever |
| `review` | A second model call | Does this make sense |

Only `world` and `review` rely on model judgment. Everything else is code.

## world

Quest-wide, unchanging, injected into **every** prompt. Small on purpose — a few hundred tokens, identical every turn, so prompt caching makes it nearly free after the first call.

```json
{
  "setting": "London, 1883. Late Victorian, gaslit, pre-telephone.",
  "register": "Formal, restrained. People do not say what they feel directly.",
  "physics": "realistic",
  "supernatural": "none",
  "absent": [
    "Electric light, telephones, motor vehicles, photography as casual record",
    "Modern medicine, antibiotics, forensics beyond the crude",
    "Modern food, modern slang, modern social attitudes"
  ],
  "present": [
    "Hansom cabs, telegrams, gas lamps, coal fires, servants",
    "Revolvers, railways, the Underground, calling cards"
  ],
  "anachronism_response": "Do not refuse out of character. The thing simply does not exist and the world does not acknowledge the concept. If the player asks for a telephone, there is no telephone — not 'telephones have not been invented', just no telephone in the room and no idea what one would be.",
  "weirdness": 0
}
```

**`absent` is illustrative, never exhaustive.** You cannot enumerate what doesn't exist. It is there to establish a *pattern* the model generalizes from, not a blocklist. This is the one place the design deliberately relies on model judgment over code, because it is the only thing that scales to inputs nobody anticipated.

**`weirdness`** — 0 to 10. How far the model may invent beyond what's declared. At 0 it stays strictly inside the frame. At 8 it improvises freely and the frame is a suggestion. Default 2. This is the deliberate-fuzziness dial: a dream sequence, a surreal quest, or a comedy sets it high on purpose.

**Generated, not written.** "Victorian London, 1883, no supernatural" is enough input for a builder agent to produce all of the above. The author corrects it; they never compose it.

## clock

v2's four named phases were too coarse to mean anything — a conversation and a journey to Surrey both just "happened." v3 tracks story-time in minutes, because time *is* quantifiable, unlike coherence.

```json
{
  "starts_at": "1883-04-06T07:15:00",
  "default_turn_cost_minutes": 2,
  "phases": [
    { "name": "morning", "until": "12:00" },
    { "name": "afternoon", "until": "18:00" },
    { "name": "dusk", "until": "20:30" },
    { "name": "night", "until": "05:00" }
  ],
  "deadline": {
    "at": "1883-04-07T03:00:00",
    "meaning": "Whatever killed Julia comes for Helen.",
    "on_reached": "e_too_late"
  }
}
```

Exits and beats may declare `costs_minutes`. Travel to Surrey costs 180; examining a room costs 5. The engine advances the clock; the model never touches it, and is told the current time and phase each turn so narration stays consistent with it.

**`deadline` is the backstop for the whole quest.** No session can run forever, because story-time always advances. This is termination guaranteed at the top level, independent of any scene.

## pressure

The mechanism v2 lacked entirely, and the reason old text adventures felt dead. They had exactly two responses to a drifting player: allow it, or refuse it. Refusal repeated verbatim is what made them lifeless.

Pressure is the third response: **do not refuse — bend the world toward the plot.**

```json
{
  "idle_after_turns": 3,
  "escalation": [
    "Watson glances at the clock on the mantelpiece.",
    "Helen says quietly that she must be home before her stepfather notices she has gone.",
    "Helen stands and reaches for her gloves. She is running out of time."
  ],
  "on_exhausted": "helen_departs"
}
```

A turn counts as **idle** when it sets no flag, triggers no discoverable, takes no exit, and fires no guarded event. Three idle turns and the world nudges. Six and it nudges harder. When escalation is exhausted, the named guarded event fires — the opportunity genuinely closes.

Nobody is told they can't do something. The story simply applies gravity. This is also what prevents the fifteen-turn "Watson is two minutes gone" loop: idle turns cannot accumulate indefinitely.

## guarded_events

From v2.1, unchanged in mechanism. Any narrated consequence that changes what's reachable — a character leaving, a door locking, an opportunity expiring — is validated exactly like an exit.

```json
{
  "id": "helen_departs",
  "trigger": "player dismisses Helen, refuses to help, or the interview otherwise ends",
  "requires": "heard_the_account",
  "on_blocked": "Something holds her a moment longer. She hesitates, or Watson asks one more question. She does not actually go.",
  "on_allowed": { "degrade": "no_account", "goto": null }
}
```

`on_allowed.degrade` is new, and it is the important part.

## degradation

The lesson from every quest game that punished failure with a restart: **the player who died and replayed the same scene is the player who stopped playing.**

Failure should cost something other than the player's time. When a guarded event fires without its `requires` met, instead of blocking *or* dead-ending, the quest can continue in a **worse state**.

```json
"degradations": {
  "no_account": {
    "description": "Helen left before telling you about the whistle or the locked door.",
    "sets": ["missed_account"],
    "unlocks": ["to_surrey"],
    "consequences": [
      "The night watch is far harder — you do not know to expect a sound.",
      "You will not recognise the significance of the ventilator without prompting."
    ],
    "still_winnable": true
  }
}
```

You can still go to Stoke Moran. You just don't know what you're looking for. The story continues, meaningfully damaged, and the win is still theoretically reachable — harder, and possibly not by this player.

`still_winnable: false` is permitted, but then the degradation **must** name an ending it eventually routes to. A degraded path that cannot win and cannot end is exactly bug #2 above, and the validator rejects it.

## termination

Three independent backstops, so no session can run forever regardless of what the player does or what the author forgot:

**Scene budget.** Every scene has `max_turns` (default 25). On exceeding it, the engine forces the scene's `on_exhausted` transition, or a universal ending if none is declared.

**Universal endings.** A small set of generic fail states every quest inherits, so no branch needs a bespoke ending authored for it:

```json
"universal_endings": [
  { "id": "u_too_slow", "result": "loss", "direction": "The moment passed while you were elsewhere. Do not explain what was missed." },
  { "id": "u_turned_away", "result": "loss", "direction": "You were asked for help and did not give it. The story went on without you." },
  { "id": "u_lost_thread", "result": "loss", "direction": "Whatever you were following is gone. Do not explain what it was." }
]
```

**The deadline**, from `clock`, above everything.

## review

The one place a second model call is justified — not because agents are fashionable, but because "does this make sense" is not a predicate and code cannot evaluate it.

```json
{
  "enabled": true,
  "checks": ["continuity", "anachronism", "tone", "time"],
  "on_fail": "retry_once",
  "model": "cheap"
}
```

After the narrator returns a turn and the engine validates it structurally, a second, cheap call asks a narrow question: does this contradict something established, does it violate the world frame, is the tone wrong for the moment, has story-time moved implausibly? It sees the world frame, the last few turns, the invented list, and the proposed narration. It returns pass/fail plus a reason.

**It cannot rewrite.** It can only reject, causing one retry with the reason attached. Two failures commit the original — a dull turn is better than an infinite loop.

Disable it for speed; enable it for quality. It is the only per-turn cost in v3 that is genuinely optional.

## Turn contract

```json
{
  "narration": "1-3 sentences.",
  "exit_id": "legal exit id, or null",
  "guarded_event_id": "legal guarded event id, or null",
  "discovered": ["discoverable ids"],
  "disposition_changes": [{ "character": "helen", "direction": "up", "reason": "..." }],
  "invented": ["details invented this turn"],
  "minutes_elapsed": 2,
  "refused": false
}
```

`flags_set` is **removed**. v2 asked the model to report flags that `discoverable.sets` and `exit.sets` already declare — redundant bookkeeping that smaller models silently dropped, making the whole quest un-progressable until it was fixed. The engine derives flags from validated ids. **General rule: never ask the model to report anything the engine can derive.**

`minutes_elapsed` is a suggestion; the engine uses the declared `costs_minutes` where one exists and falls back to the model's estimate only for free-form turns.

## Validator rules

All v2 rules, plus:

**Errors**
- A degradation with `still_winnable: false` that names no reachable ending
- A scene with no `max_turns` and no `on_exhausted` and no exit reachable from every state
- `pressure.on_exhausted` naming a guarded event that doesn't exist
- A guarded event whose `on_allowed.degrade` names an undeclared degradation
- A deadline that cannot be reached, or that is reachable before the win path can complete
- Any character gating a required flag with no guarded event covering their departure *(bug #1)*
- Any scene from which required flags can become permanently unavailable with no ending reachable *(bug #2)*

**Warnings**
- `world.absent` with fewer than three entries — the model needs a pattern, not a rule
- No `pressure` on a scene with more than four exits or discoverables
- A degradation declared but unreachable
- `weirdness` above 5 with a `physics: realistic` frame

## Authoring reality

Six mechanisms is more than any casual author will fill in. That is accepted, and it is the reason for the split:

**The builder agent generates all of it** from a premise. World frame from era and genre. Pressure from what each scene needs the player to do. Time costs from what actions plausibly take. Degradations from what each gate protects.

**The author corrects, never composes.** They see a world frame and say "no, it's 1920 not 1880." They see a pressure escalation and say "she wouldn't say that." Correction is a far lower bar than authorship, and it is the only version of this that a non-writer will finish.

**Every field has an inferred default.** A quest with no `pressure`, no `degradations`, and a bare `world` still validates and still plays. It plays worse. Nothing is mandatory except what the validator needs to guarantee termination.
